Triviall docs

Triviall is a platform for party games. A game provides rules and three views of its state. The platform provides everything around it. This repository is the first slice: the game engine, two games, a shared UI kit, and a lab for reviewing them.

Quickstart

You need Node 20 or newer, Python 3, and make. There are no packages to install.

make test     # run the engine and game tests
make check    # tests plus a link and import check for the site
make serve    # serve the site at http://localhost:8080

Open http://localhost:8080/lab/ to review the games. Pages must be served over HTTP because the site uses ES modules.

Open in a Codespace

The .devcontainer/ folder runs scripts/bootstrap.sh after creation and scripts/start.sh on every start, serving the site on port 8080. This is the static site only. Open the forwarded port, then go to /lab/. The start script tries to make the port public with the gh CLI, which is spike check A1 and unverified. If it fails, set the port's visibility to Public in the Ports tab.

Publish on GitHub Pages

The site is plain static files at the repository root, so there is no build step.

  1. Push the repository to GitHub.
  2. Open Settings, then Pages. Under Build and deployment choose Deploy from a branch.
  3. Pick your default branch and the / (root) folder, then save.

The landing page is index.html, the lab is lab/, and these docs are docs/. The empty .nojekyll file keeps GitHub from processing the files. All links are relative, so the site works under a project path such as /triviall/.

Three views

The room is the only holder of full game state. It asks the game for a separate view per client role, so a secret never reaches a client that should not have it.

RoleReceivesCan do
DisplayPublic presentation onlyNothing. It is read-only.
HostRoom status and controlsStart and skip. It sees no hidden roles.
PlayerOwn private viewSubmit inputs allowed for the current phase.

A device is not an identity. The room keys everything by player id, so one phone can later be a player and a display sender at once. The lab does not demonstrate that yet.

Game contract

A game is a plain ES module. It must be pure: no clocks, sockets, or storage. Time arrives as now, and randomness comes from a seeded generator stored in the state, so the same seed and inputs always give the same game.

export const manifest = { id, name, version, sdk: 1, minPlayers, maxPlayers, ... };
export const secretKeys = ['role', ...];          // must never appear in a display payload
export function create(config, { seed, content }) // returns state
export function join(state, { id, name })         // returns { state } or { error }
export function handleInput(state, playerId, input, now)
export function handleHostCommand(state, cmd, now)
export function handleTimer(state, now)           // returns { state } or null
export function getDisplayView(state)             // public only
export function getHostView(state)
export function getPlayerView(state, playerId)
export function debug(state)                      // lab reviewer view only

Views use shared shapes so the UI kit can draw them. A player view has headline, lines, an optional prompt with options, and an optional timer. A prompt option is sent back as { type: prompt.kind, choice: option.id }. Timers are absolute deadlines, so a reconnecting client never resets a countdown.

This slice uses one deadline per phase. The full spec also describes scheduled effects and an async prepare step. Those arrive with the server.

Add a game

  1. Create games/your-game/index.js exporting the contract above.
  2. Add it to GAMES in lab/lab.js and to the picker in lab/index.html.
  3. Write tests. Reuse tests/helpers.js for a fake clock, and check findLeaks against the display view for every phase.
  4. Run make check. A game needs no casting, room, or networking code.

Trivia

  • 20 questions by default, adjustable from 1 to 50. The default game makes one request to the Open Trivia Database when the room is created.
  • Questions use URL encoding and are decoded on load. If the API is unreachable, rate limited (one request per IP every 5 seconds), or returns too few questions, the game uses the bundled set and says so in the host panel.
  • Scoring: a correct answer earns 1000 points, scaled down to 500 as time runs out. The first answer locks.
  • The correct answer is not in any payload until the reveal.
  • Questions are licensed CC BY-SA 4.0. The final screen shows the attribution. Check the ShareAlike terms before republishing question sets.

The bundled set has 20 questions. The spec asks for at least 50.

Phases run reveal, night, dawn, day, vote, verdict, and repeat until a side wins. Werewolves win when they equal the rest of the village, and villagers win when none remain.

  • The display shows only public facts. Living players never carry a role tag, and night text is the same every night.
  • Every player gets a night prompt of the same shape. Villagers get a decoy prompt, and the night always ends at its deadline, so speed reveals nothing.
  • The host sees no roles, so the host can also play. Use the lab's reviewer view to see hidden state.
  • Dead players see public information only.

Verification spike

These assumptions came from memory and need a real test before the server is designed around them. In a Codespace, scripts/spike.mjs runs on every start and records the automated checks (A1, A2, A5, A6b) in docs/spike-results.md and docs/spike-results.json. It cannot send them anywhere: commit and push the two files, or share them, to pass results back. Device checks go in the manual table in that file. Run make spike to refresh by hand.

  • Codespaces can make the app port public without a manual step, and an anonymous phone can load it.
  • The QR origin built from Codespaces environment variables is reachable from outside.
  • WebSockets survive idle periods and reconnect quickly through port forwarding.
  • A private admin port can bootstrap the first host credential.
  • The web Cast sender works on desktop and Android Chrome but not on iOS. A receiver needs a registered app and a stable HTTPS URL.
  • The Open Trivia Database is reachable from a Codespace despite its per-IP rate limit.
